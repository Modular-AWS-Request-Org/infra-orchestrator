AWS self-service provisioning

Compose infrastructure the same way you compose products.

Authenticate with GitHub, pick the AWS services your team needs, review the generated infra.yaml, and trigger an end-to-end provisioning run in infra-orchestrator.

1. Authenticate

Enter a GitHub PAT with access to the Modular-AWS-Request-Org organization. It is stored in sessionStorage only and is cleared when the tab closes. Production would use GitHub OAuth instead.

The app validates your token with GitHub and confirms your membership in the org.

2. Project setup

Choose a repo name, deployment region, and team tag. The repo name is also used throughout the generated Terraform.

Must match ^[a-z][a-z0-9-]{2,39}$.

3. Service selection

Toggle any combination of modules. The workflow provisions only what you select.

4. Service configuration

Defaults are pre-filled. Sections appear only for the services you select.

Frontend

Static hosting through S3 and CloudFront.

Database

DynamoDB with managed encryption and PITR enabled.

Storage

Secure S3 storage with configurable versioning.

Compute

Lambda with a placeholder handler and optional URL.

5. Review and create

The payload is assembled live. Only selected services appear in the generated configuration.

Provisioning requested

GitHub accepted the dispatch. The new repo usually appears within about 15 seconds.
